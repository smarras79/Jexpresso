# Elasticity

Elastic deformation as first-order hyperbolic conservation laws, which is the
form that fits a SEM/DG solver: two 2D cases on their own gmsh grids, plus the
1D Timoshenko beam the set started from. And one QUASI-STATIC case — a
viscoelastic solid with no inertia, one linear solve per time step — on the
`:lquasistatic_solid` path.

```bash
julia --project=. src/Jexpresso.jl Elasticity beam2d                  # a loaded beam
julia --project=. src/Jexpresso.jl Elasticity plane_wave2d             # verification
julia --project=. src/Jexpresso.jl Elasticity timoshenko1d             # reduced model
julia --project=. src/Jexpresso.jl Elasticity viscoelastic_cylinder2d  # creep, quasi-static
julia --project=. src/Jexpresso.jl Elasticity plastic_cylinder2d       # J2 plasticity, quasi-static
```

| case | dim | eqs | grid | boundaries |
|---|---|---|---|---|
| `beam2d` | 2D | 7 | `beam_32x6.msh` | hinged supports + loaded/free surfaces |
| `plane_wave2d` | 2D | 5 | `square_periodic_16x16.msh` | none (doubly periodic) |
| `timoshenko1d` | 1D | 4 | built-in | simply supported |
| `viscoelastic_cylinder2d` | 2D | 2 (ux, uy) | `quarter_annulus_4x8.msh` | pressure inside, free outside, 2 symmetry rollers |
| `plastic_cylinder2d` | 2D | 2 (ux, uy) | `quarter_annulus_8x8.msh` | bore displaced, free outside, 2 symmetry rollers |

The grids are structured quad meshes generated by `make_meshes.py`
(`pip install gmsh && python3 problems/Elasticity/make_meshes.py`). One gmsh
quad becomes one spectral element carrying (nop+1)² LGL nodes.

## The 2D system: velocity–stress elastodynamics

State, plane strain, per unit volume:

```
U = (ρu, ρv, σxx, σyy, σxy)ᵀ
```

Balance of linear momentum plus the rate form of Hooke's law:

```
∂ₜ(ρu)  = ∂ₓσxx + ∂_y σxy
∂ₜ(ρv)  = ∂ₓσxy + ∂_y σyy
∂ₜσxx   = (λ+2μ) ∂ₓu + λ ∂_y v
∂ₜσyy   = λ ∂ₓu + (λ+2μ) ∂_y v
∂ₜσxy   = μ (∂_y u + ∂ₓv)
```

i.e. `∂ₜU + ∂ₓF(U) + ∂_y G(U) = 0` with

```
F(U) = -(σxx, σxy, (λ+2μ)u, λu,      μv)ᵀ
G(U) = -(σxy, σyy, λv,      (λ+2μ)v, μu)ᵀ
```

**The source is empty.** Every term is a divergence. That is the structural
difference from Timoshenko, whose shear coupling `κₛGAγ` and whose `-ω` are
undifferentiated and therefore have to sit in `S`.

### Characteristics

The flux Jacobian in any direction **n** has eigenvalues

```
±cp = ±√((λ+2μ)/ρ)     pressure (P) wave
±cs = ±√(μ/ρ)          shear (S) wave
 0                     the stress combination carrying no motion along n
```

so the system is hyperbolic, and symmetrizable by the mechanical energy

```
½ρ(u² + v²) + ½ σ : C⁻¹ : σ
```

which is the convex entropy; its flux is `-σ·v`, the mechanical power. Standard
upwind or Rusanov fluxes apply directly — these cases run on Jexpresso's
continuous SEM, so no Riemann solver is used, but the structure is there for a
DG variant.

Two incoming characteristics per boundary, so each boundary takes exactly two
conditions: a clamp supplies the two velocity components, a free surface
supplies the two components of the traction `σ·n`.

### Material

All three cases use the same non-dimensional material, defined once per case in
`elastic_properties()` / `timoshenko_properties()` in `user_flux.jl`:

| | |
|---|---|
| ρ = 1, E = 1, ν = 0.3 | → λ = 0.576923, μ = 0.384615 |
| cp = 1.160239 | P wave |
| cs = 0.620174 | S wave, cp/cs = 1.8708 |

In **plane strain** the bending modulus is `E/(1-ν²) = 1.0989`, not `E` — a
plane-strain beam is stiffer than the 1D beam model by that factor, which is
why `beam2d` and `timoshenko1d` do not report the same frequency.

### Stabilisation — read this before running anything undamped

A continuous-Galerkin spectral element discretisation of a first-order
hyperbolic system, run **undamped** for tens of thousands of steps with
strongly imposed boundary values, grows an element-scale checkerboard mode.
This is not hypothetical: an earlier `cantilever2d` in this directory shipped
with `:lvisc => false` and reached σyy ≈ 1e+276 by the eighth output frame —
about 2.6% growth per step, from round-off.

`beam2d` is stabilised primarily by the **Boyd–Vandeven modal filter**
(`:lfilter => true, :filter_type => "erf"`), which is the right tool for this
failure: `init_filter` leaves every mode up to 2p/3 *exactly* alone and rolls
off above it, so at p = 4 the transfer weights are

| mode | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| weight | 1 | 1 | 1 | 0.9957 | 0 |

— a top-mode-only filter that deletes the mode the checkerboard lives in and
does not touch the resolved solution. Compare a Laplacian, which damps every
wavenumber including the beam's own bending mode.

`:mu_x` / `:mu_y` are **blend factors** in [0,1], one per reference direction:
`init_filter` builds `F = μ·F_BV + (1-μ)·I`. They are not viscosities and do not
scale with Δx. The filter runs once per **RK stage**, so five times per step
with `CarpenterKennedy2N54`; at `μ = 0.05` that removes 22.6% of the top mode
per step, against the ≈2.6% per step the instability grew at.

A residual `AV()` viscosity is kept alongside it at a tenth of its former value
(2e-5, ≈0.4% of the bending mode over the run) purely as a backstop, because at
p = 4 the filter really only bites on one mode and the original failure has
never been re-run to establish which mode it lived in. **Once a run confirms the
filter holds alone, set `:μ` to zeros and `:lvisc => false`** — that is the
preferred end state, since `∇²σ` has no physical meaning and the filter does the
job without inventing one.

`plane_wave2d` is deliberately left with neither. It is the verification case —
a filter would delete the top modal coefficient and read as amplitude loss that
is not the scheme's — and it is the diagnostic: it has no boundaries at all, so
if it blows up the problem is the volume operator, and if it stays clean for ten
periods the boundaries are where to look.

**The filter is 2D/3D only.** `filter!` has no `NSD_1D` method, so
`:lfilter => true` in a 1D deck raises a MethodError rather than filtering;
`timoshenko1d` says so in place.

## `plane_wave2d` — the verification case

An oblique plane P-wave on a doubly periodic unit square. With
**k** = (2π p/L, 2π q/L), **n** = **k**/|k| and φ = **k**·**x** − ωt, ω = cp|k|:

```
displacement   A n sin(φ)
velocity       -A ω n cos(φ)
stress         σij = A|k| (λ δij + 2μ ni nj) cos(φ)
```

Integer p, q make **k**·**x** periodic in both directions, so the wave simply
re-enters. `p = q = 1` puts it on the diagonal, which is what makes this a real
2D test rather than a 1D solution embedded in a 2D mesh: all five components are
active and both flux directions carry the wave.

**There are no boundaries at all.** What is being checked is the flux operator,
the metric terms and the periodic node matching, against an exact solution, with
the boundary treatment taken entirely out of the picture.

**The check:** the wave is exactly time-periodic with T = 2π/(cp|k|) = 0.6094494.
`:diagnostics_at_times` lands on whole multiples of T, so **every output frame
must reproduce the t = 0 frame**. Ten periods in, whatever has drifted is
dispersion and time-integration error and nothing else.

## `beam2d` — a beam on two supports with a load in the middle

The textbook problem, solved as a time-dependent 2D elastic body with no beam
theory anywhere in it: span 1, depth 0.2 (L/h = 5), hinged at both ends, with a
downward pressure pressed onto a patch of the top surface at midspan.

Seven equations: the five above plus **displacement recovery**,

```
U₆ = ux     ∂ₜux + ∂ₓ(0) + ∂_y(0) = vx
U₇ = uy     ∂ₜuy + ∂ₓ(0) + ∂_y(0) = vy
```

Zero flux, so they add two zero eigenvalues and change neither the
characteristic structure nor the stable time step. They are reconstructions, not
conservation laws — but they are what makes the output a sagging beam.

> **Naming, because the output does not warn you:** `vx`/`vy` are the particle
> **velocity**; `ux`/`uy` are the **displacement**. The sag is `uy`.
>
> Field names are deliberately **ASCII** (`sxx`, `syy`, `sxy`). A Greek σ does
> not survive the trip into VTK — a field written as `σyy` turns up in VisIt
> under the name `yy`.

Boundary conditions — one per characteristic family at each boundary:

| tag | family | imposed | free |
|---|---|---|---|
| `support` (both ends) | S | `vy = 0` — held at height 0 | `vx`, `σyy`, `σxy` |
| | P | `σxx = 0` — no axial reaction | |
| `top` | P | `σyy = -p(x,t)` — the load | `vx`, `vy`, `σxx` |
| | S | `σxy = 0` | |
| `bottom` | P | `σyy = 0` | `vx`, `vy`, `σxx` |
| | S | `σxy = 0` | |

Leaving `σyy`, `σxy` and `vx` free at the supports is exactly what makes them
**hinges** and not clamps: the end face may rotate and slide axially. Two
rollers rather than a pin-and-roller leaves rigid-body horizontal translation
unconstrained, deliberately — the loading is symmetric and vertical, so `vx`
stays antisymmetric about midspan and the beam never drifts, whereas pinning
`vx` would put a spurious axial reaction into a problem that has no axial load.

**The initial state is all zeros** — undeformed, unstressed, at rest — and the
load is *ramped* rather than switched on, over `tramp = 4` (≈ 4.6 wave transits
of the span, ≈ 0.36 of a bending period). Both matter: every boundary condition
is then satisfied exactly at t = 0, so there is no incompatibility for the
scheme to ring on. Switching a load on instantaneously is a step in time at that
face and launches a front; the load's `cos²` profile in x is smooth for the same
reason.

**What to expect.** Midspan `uy` settles around **−9.70e-3**, after first
swinging to roughly twice that — an undamped beam released onto a load
overshoots to 2× the static deflection. Beam theory splits that as

```
bending  P L³/(48 E′ I)  = 8.53e-3
shear    P L /(4 κₛGA)   = 1.17e-3     — 12% of the total, which is why L/h = 5
```

`σxx` is the bending stress: tension on the bottom fibre, compression on the
top, largest at midspan, ±1.1e-2. `σyy` stays small away from the loaded patch.
All of these numbers are printed by `initialize.jl` at startup, so the run tells
you what it is aiming at before it starts.

## `timoshenko1d` — the reduced model

The shear-deformable beam as a 1D first-order hyperbolic system:

```
U = (ρA v, ρI ω, γ, χ)ᵀ

v = ẇ,  ω = φ̇,  γ = w_x - φ,  χ = φ_x

F(U) = -(κₛGA γ, EI χ, v, ω)ᵀ        S = (q, κₛGA γ, -ω, 0)ᵀ
```

Rows 1–2 are balance of linear and angular momentum, with fluxes minus the shear
force `Q = κₛGA γ` and the bending moment `M = EI χ`; rows 3–4 are the
compatibility conditions `γ̇ = v_x - ω` and `χ̇ = ω_x`. `κₛGA γ` and `-ω` sit in
the source because they are **undifferentiated**, not because they are
nonlinear: the system is linear with constant Jacobian, whose spectrum splits
into two decoupled pairs at ±√(κₛG/ρ) and ±√(E/ρ), symmetrizable by
½(ρA v² + ρI ω² + κₛGA γ² + EI χ²).

Euler–Bernoulli has no such form: its fourth-order operator makes it dispersive,
not hyperbolic, and the best two-field form has second-order fluxes wanting an
LDG-type treatment rather than a Riemann solver. It is recovered here as the
stiff relaxation limit κₛGA → ∞ (γ → 0).

The case is the first flexural standing mode of a simply supported beam,
released from rest. Ω is the lower (flexural) root of the Timoshenko frequency
equation

```
(ρIρA/κₛGA) Ω⁴ - [ρI k² + EI ρA k²/κₛGA + ρA] Ω² + EI k⁴ = 0
```

giving Ω = 0.28023 against the Euler–Bernoulli 0.28491 — the 1.6% shear
flexibility costs at L/h = 10 — and a period T = 22.4215, which is exactly
`:tend`. `user_analytic.jl` supplies the exact solution, so the shared 1D
plotter overlays it on **every** output frame: the gap between the two curves is
entirely the discretisation's, and after one full period every field must land
back on its initial profile.

**Large deformation.** The geometrically exact (Simo–Reissner) beam keeps the
same shape — `∂ₜ(ρA 𝐯) - ∂ₓ𝐧 = 𝐧̄`, `∂ₜ(𝐈ω) - ∂ₓ𝐦 = 𝐱,ₓ × 𝐧 + 𝐦̄` — but
`𝐧, 𝐦` become nonlinear functions of the strain measures through the rotation
field, and the angular momentum source picks up the `𝐱,ₓ × 𝐧` term.

## `viscoelastic_cylinder2d` — creep of a thick-walled cylinder (quasi-static)

The first benchmark of E. Artioli, L. Beirão da Veiga, C. Lovadina, E. Sacco,
*Arbitrary order 2D virtual elements for polygonal meshes: Part II, inelastic
problem*, Comput. Mech. 60 (2017), arXiv:1701.06676 — Secs. 3.1 and 4.2 —
here with order-4 spectral elements.

A cylinder `a = 2 ≤ r ≤ b = 4` in plane strain, internal pressure `p = 10`
switched on at `t = 0` and held to `t = 20`, outer surface free. A quarter of
the cross-section, with symmetry rollers on the two straight edges:

| tag | where | condition |
|---|---|---|
| `inner` | r = a | traction σ·n = −p n |
| `outer` | r = b | traction-free |
| `xaxis` | y = 0 | u_y = 0 |
| `yaxis` | x = 0 | u_x = 0 |

**Material** (paper eqs. 3.5–3.7): generalized Maxwell in the deviator, elastic
in volume, one Prony term,

```
G(t) = G (μ₀ + μ₁ e^{−t/λ}),   λ = 1,   E = 1000, ν = 0.3  →  G = 384.6, K = 833.3
ve1: (μ₀, μ₁) = (0.01, 0.99)      ve2: (μ₀, μ₁) = (0.3, 0.7)
```

> **λ here is the RELAXATION TIME, not the Lamé constant.** The code calls it
> `τ` because the Lamé λ = K − 2G/3 lives in the same solver.

### The quasi-static path

There is no inertia: `:lquasistatic_solid => true` sends the run to
`src/kernel/solvers/quasistatic_solid.jl` instead of the time integrator, and
every time step is one linear solve. Its spatial discretisation is entirely
Jexpresso's own — the grid, LGL basis, metric terms and quadrature of
`sem_setup`; the stiffness from `build_gradient_product_matrices` (the
directional components of `build_laplace_matrix`, `Lxx + Lyy = Le`) assembled
by `DSS_laplace_sparse`; tractions by `compute_segment_integral!` /
`DSS_segment_integral!`; stresses by `_∇f!` + `DSS_rhs!` + the lumped mass;
output by `write_output`. The solver adds the material and its time recursion.

**Time integration.** Each Maxwell internal variable obeys `q̇ + q/λ = ė`; over a
step it is updated by the exponential recursion

```
qⁿ⁺¹ = e^{−Δt/λ} qⁿ + γ (eⁿ⁺¹ − eⁿ),     γ = (λ/Δt)(1 − e^{−Δt/λ})
```

exact for a strain linear in time over the step — Simo & Hughes,
*Computational Inelasticity* Sec. 10.3, in the form of Zienkiewicz, Taylor &
Fox (2014) that FEAP and the paper use. It is second order.
`:viscoelastic_integrator` also offers `"midpoint"` (S&H Box 10.1,
γ = e^{−Δt/2λ}, also second order) and `"backward_euler"` (first order, kept as
the control a convergence study needs). Because the model is linear, the
history of every quadrature point is `dev ε` of a NODAL field obeying the same
recursion, so the whole step is sparse algebra on the two assembled operators —
the quadrature-point recursion to round-off, with no per-point storage.

**The two curved boundaries** are snapped onto their circles by
`:exact_geometry`, so the pressure acts on the isoparametric degree-4 circle
with its exact normal; gmsh alone would leave every high-order node on a chord.

### The exact solution

By the correspondence principle (load `p/s`, `G → sĜ(s)`, `K` unchanged),

```
u_r(r,t) = P [ r C(t) + (b²/2r) J(t) ],         P = p a²/(b² − a²)
J(t) = (1/G) [ 1/μ₀ − (1/μ₀ − 1) e^{−μ₀t/λ} ]                    shear creep compliance
C(t) = 1/M∞ − (1/M∞ − 1/M₀) e^{−M∞ t/(M₀λ)},   M₀ = 2K + 2G/3,  M∞ = 2K + 2μ₀G/3
```

At `t = 0` it is the Lamé solution `P (1+ν)/E [(1−2ν) r + b²/r]`. σ_rr and
σ_θθ do **not** depend on the material — both surfaces carry prescribed
tractions — so they are the Lamé stresses `P(1 ∓ b²/r²)` at every t, and in
this free-outer-surface problem the stresses do not redistribute in the plane
(they do in the case-bonded variant). What creeps is the displacement and
σ_zz, which plane strain needs to keep ε_zz = 0:

```
σ_zz(t) = 2P [ ν∞ + (ν − ν∞) e^{−t/τ_z} ],   ν∞ = (3K − 2μ₀G)/(2(3K + μ₀G)),   τ_z = λ(3K + G)/(3K + μ₀G)
```

**The displacement is the quantity to check.** All of it is in
`user_analytic.jl`, together with a second reference: the same recursion run on
the Lamé family `u_r = A r + B/r`, which this geometry never leaves — exact in
space, discrete in time with the solver's own Δt. SEM minus that is the spatial
error alone; that minus the closed form is the time error alone.

### Load convention: why the paper's first points are lower

The paper's Fig. 5.2 starts from zero at step 0 and is at u_A = 0.0583 at step
1, where the closed form gives 0.0726 at t = 1. That is not an error on either
side. FEAP applies the pressure in the FIRST increment, and the exponential
recursion assumes the strain is linear in time over a step — so the paper's
load is effectively ramped over [0, 1], not a step at t = 0.
`:linitial_elastic_solve` selects which problem is solved:

* `true` (default) — the pressure is on at t = 0⁺: an instantaneous (glassy)
  elastic solve, then the creep. This is the closed form's problem.
* `false` (`JEXPRESSO_VE_LOAD=first_increment`) — start unloaded, load in the
  first step: the paper's problem. With Δt = 1 this reproduces Fig. 5.2.

## `plastic_cylinder2d` — history at the quadrature points (J2 plasticity)

The same quarter cylinder, now **elastic–perfectly plastic** (von Mises, the
material of Artioli et al. §4.3: E = 7000, ν = 0.3, σy0 = 24.3), its bore
displaced radially from 0 to δ = 0.05 — about 9x the displacement at first
yield — over the load parameter t ∈ [0, 1]. Displacement control, because a
perfectly plastic body cannot carry a prescribed pressure above its limit; the
pressure comes back as the reaction, `p = R_inner_x / a` in `solid_history.csv`.

**What it exercises.** Plasticity cannot use the nodal-history shortcut of the
viscoelastic case: the plastic strain is not a linear function of the
displacement. `:solid_history => "quadrature"` keeps the history — eᵖ (four
components) and ēᵖ — at every quadrature point, and every increment is a Newton
iteration with the consistent tangent (`build_tangent_stiffness_matrices` +
`DSS_laplace_sparse`), the internal force being the weak divergence of the
quadrature-point stress. The same storage holds any strain-driven model: a
shape-memory alloy (paper §3.3) keeps its transformation strain where J2 keeps
eᵖ. Models are a `struct <: AbstractSolidModel` plus four methods
(`nhistory`, `islinear`, `solid_history_fields`, `solid_constitutive_update!`)
in `src/kernel/solvers/quasistatic_solid.jl`.

**What is exact here.** Up to first yield the solution is Lamé's
(p_e = 10.5047 at δ_e = 5.72e-3). Once the whole wall flows, plastic
incompressibility and plane strain give s_zz = 0 and σθθ − σrr = 2σy0/√3, so
the pressure levels off at **p_L = (2/√3) σy0 ln(b/a) = 19.4492** (Hill). In
between, the problem stays axisymmetric, and `user_analytic.jl` solves it on a
fine 1D radial grid with the same constitutive routine and increments.

| bore pressure before first yield vs Lamé | 1.9e-7, ēᵖ = 0 |
| bore pressure vs 1D radial reference, all 50 increments | 1.3e-4 of p_L |

| Newton iterations per increment | 3.8 on average, 5 at most |

## Seeing the solid deform

Both solid cases write the displacement as a VECTOR field `u` next to `ux`,
`uy` (`:vtk_vectors => [("u", "ux", "uy")]`, a general option of the 2D/3D VTK
writer). In ParaView:

1. *File → Open* `output/Elasticity/<case>/output/simulation.pvd`, *Apply*.
2. *Filters → Warp By Vector*, Vectors = `u`. Scale Factor 1 is the true
   deformation (the viscoelastic bore creeps by 16% of its radius); the plastic
   case needs ~10.
3. Colour by any field — the magnitude of `u`, `szz`, `svm`, `ep_bar`
   (the plastic strain, a quadrature-point history value projected onto the
   nodes) — and press *Play* to watch it evolve.

Without ParaView, `:lplot_deformed => true` (on in both decks) draws the
deformed spectral-element grid over the dashed undeformed outline at every
output time — `deformed-<field>-it<k>.png` — and strings the frames into
`deformed.gif`: `:plot_deformed_field` picks the colour (`umag`, any written
field, e.g. `ep_bar`), `:plot_deformed_scale` the magnification,
`:plot_deformed_clims` a fixed colour range for the animation
(`plot_deformed_mesh` in `src/io/plotting/jeplots.jl`).

Any history field can be written: list it in the case's `qvars`
(`initialize.jl`) — for J2 `ep_bar`, `ep_xx`…`ep_xy`, `alpha_xx`…`alpha_xy`;
for the viscoelastic model on the quadrature path `q1_xx`…; plus `svm` (von
Mises stress) and `umag` (|u|) for any model.

## A bug this equation set flushed out

Building the 1D cases turned up a real defect in the 1D SEM kernels, fixed in
the same branch. The 1D volume term weighted the flux by `ω[i]` and the source
by `ω[i]`, and the assembled result is divided by the lumped mass matrix
`M[i] = Je[i]·ω[i]`:

```
flux:    ω·dFdξ  / (Je·ω)  =  dFdξ/Je = dF/dx    correct
source:  ω·S     / (Je·ω)  =  S/Je               wrong by 2/Δx
```

The flux is right *by cancellation*: in 1D `dF/dx = dFdξ·dξdx` with
`dξdx = 1/Je`, so weighting by `ω·Je` would immediately undo itself and the
kernel simply never wrote `Je` at all. The source has no `dξdx` to cancel
against, so the same (absent) weighting left it scaled by `1/Je`. **The 2D and
3D kernels form `dF/dx` explicitly and then weight by `ω·Jac`, so only 1D was
affected** — in all of its paths at once: `_expansion_inviscid!` and
`_expansion_inviscid_laguerre!` on the CPU, and `_build_rhs_gpu_v0!` on the GPU.

Nothing caught it because only four 1D cases have a live source and all four are
*sponges*, whose coefficient is a free tuning knob that absorbed the factor. The
one 1D case with a genuinely physical source, `CompEuler/nozzleanderson`, is not
in CI. `CompEuler/wave1d_lag` *is*, and its `Je = 0.05` is the same in the CG and
the Laguerre region, so the compensating `1/0.05` is folded into that deck and
its solution is unchanged to round-off.

The 2D cases here are unaffected either way: `plane_wave2d` has no source at
all, and `beam2d`'s displacement recovery goes through the 2D path, which was
always correct.
